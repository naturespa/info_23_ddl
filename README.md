## 実験の作り方

1単元あたり実験3〜5個＋応用ミッション1つです（v33で重複していた5枚を統合しました）。
つながりのある実験は、途中で切らずに1つのカードにまとめました（D2の1の補数と2の補数、A4の正規分布、A8の時系列）。

- **答えだけを出さない。導き方を必ず画面に出す** — この教材のいちばん大事な決まりです。
  数値を計算するカードには、必ず次の3つを置いています。

  1. **式**（`Formula`）— 記号だけでなく日本語の意味を併記します。
     例:「2進数 ＝ 商が0になるまで2で割り続け、そのつど出た余りを下から上へ読んだ並び」
  2. **手順**（`Steps`）— ①②③…と、その段で何をしたかが読めるラベルで並べます。
     最後の段の値が、下の答えとそのままつながります。
  3. **答え**（`Results`）— 各項目に「この数字がどこから来たか／何が言えるか」を必ず添えます（296項目すべて）。

  ノートと鉛筆で同じ答えを再現できることを基準にしています。
  分類や比較のカード（ヒストグラムの型、OSの役割など）は計算がないので、代わりに
  **「何を見て、何が言えるか」を1文**で必ず置いています。

- **1つの実験で1つのことを完結させる** — 以前は「入力するカード」と「その結果を表示するだけのカード」が
  分かれていて、生徒が「何を触れば動くのか」を見失っていました。関連する内容はタブでまとめ、
  入力欄は1組だけにしています。

- **1画面に「入力」と「答え」が収まる** — 値を変えたのに、答えを見るためにスクロールが必要では
  実験になりません。**1366×768（表示90%）を基準**に全カードを実測し、余白・文字サイズ・図の大きさを
  詰めました。入力欄の上端から最初の答えの下端までは、いちばん長いカードでも527pxです。
  行数の多い表と大きな図は高さを抑えて内側でスクロールさせ（表の見出しは固定）、
  棄却域の図は広い画面では図と説明を横に並べます。

  | | 修正前 | 修正後 |
  |---|---|---|
  | カードの高さ（中央値） | 781px | 597px |
  | いちばん高いカード | 1,640px | 1,063px |
  | 入力→答えが1画面に入らないカード | 多数 | **0 / 103** |

- **理論は箇条書き（原則3行）** — 各実験の冒頭の理論は、1行＝1つの要点になるように書きます。データは
  `lessons-digital.ts` / `lessons-data.ts` の `theory` で、**改行（`\n`）が箇条書きの区切り**です。
  全89か所の平均は3.3行、最も多い所でも5行に収めています（正規分布や検定など、どうしても要点が多い実験）。
  1行が2行に折り返すくらいの長さが上限の目安です。
- **理論 → ねらい → 入力 → 手順 → 答え → ヒント が同じ言葉でつながる** — 理論で「けたの重み」と書いたのに
  画面が「係数」になっている、といった言い換えをなくしました。統計記号（μ σ x̄ Σ r R² ρ α df χ²）は
  各単元の初出で読み方と意味を添えています。
- **押して開くヒント** — つまずきやすい34か所に「ヒントを見る」を置いています。最初は閉じているので、
  自力で考えたい生徒のじゃまをしません。開くと、たとえ話を1つ含む2〜3文の説明が出ます。
  例：2の補数なら「時計の針を9時間もどす代わりに3時間すすめても同じ時刻になる」。
- **言葉づかい** — 高校1〜2年生が止まる表現を洗い出して直しました。
  「基数」「正規化」「帯域幅」「窓幅」「利用率ρ」などの用語は、初出のカードで日常語に開いています。

### そうび（重要語句を集める）

「そうび」には全238語が並びます。うち**重要語句テストに出る95語は、最初は「？？？」で伏せてあります**。
その語をテストで正解すると、★がついて語句が出てきます。意味はいつでも読めるので、
「意味は分かるが、名前がまだ出てこない」状態がそのまま画面に見えます。

- ☆＋「？？？」… まだ集めていない。**その場で打ちこめる入力欄が出ます**
- ★＋語句 … 集めた（1回目・2回目どちらの正解でも集まります）
- ★のつかない143語 … テストには出ないので、最初から見えています

**テストで取れなかった語も、そうびの中で打ち直せば集まります。**
1文字違いなら「おしい！」と出るのはテストと同じです。

**この打ち直しで得点は一切動きません。**重要語句テストの点は、テストで出したときのままです。
そうびは「覚えたかどうか」、テストは「あのとき取れたかどうか」を見るもの、と役割を分けています。

JSONでは両者を分けて出力します。

| 項目 | 中身 |
|---|---|
| `wordSubmissions` | 重要語句テストの記録（得点はここだけ） |
| `practiced` | そうびの中で覚え直して集めた語。**得点には入りません** |

集めた数は、そうびの見出し・単元ごとの行・ステータス画面のコマンド（「集めた 12/95」）に出ます。

## 重要語句テスト

各単元5語、全19単元で95語。**意味を読んで語句を入力**します。確認問題の前に置いてあります。

- 問題文は「次の意味にあてはまる語句を答えなさい」という形にそろえ、各問に
  **答えの文字の種類と文字数**（「カタカナ3文字」「漢字4字」「アルファベット2文字」など）を出しています。
  この表示は `word-check.ts` の `answerShape()` が**正解の文字列から自動で作る**ので、語を足しても書き分けは要りません。
- 2回ルール（1回目正解＝1点、2回目正解＝0.5点）。1回目を間違えたときの「最初の1文字」は**有料ヒント（5G）**で、
  単元ごとに1つ買うとその単元の5語ぶん出ます。
- 打ち方のちがい（全角半角・英字の大小・長音・スペース・中黒）は自動でそろえてから照合します。1文字違いは「おしい！」と出して、×にせずもう一度打たせます。

**問題文の点検（v32）**

- 意味が通らない・何を答えるのか分からない **41語** の問題文を書き直しました
  （例：「符号なしのデータを扱う。空いたビットには必ず0が入る。」→「符号を考えないときに使うシフト。空いたビットには必ず0を入れる。」）。
- **答えが問題文の中に出てしまっている**ものを全部つぶしました。自分の答え・別解表記（`alt`）・**同じ単元の他の問題の答え**の3種類を機械的に照合しています。
  たとえばD3は「浮動小数点」が4問の問題文に入っていて、1問読めば他の答えが分かる状態でした。
- 残してあるのは、定義がつながっている4か所だけです（分散←偏差、標準偏差←分散、p値←帰無仮説、2の補数←補数）。
  ここは「偏差を2乗した値の平均」のように、その語を使わないと定義そのものが書けないためです。

## 理解度ダッシュボード

成績ページに、送信済みの確認問題から弱点を割り出すダッシュボードがあります。

- **講評** — 全体の正答率、基礎と応用の差、実験の実施状況から、事実だけを根拠にした短い所見を出します。
- **難易度別の到達度** — 基礎／共通テスト／ITパスポート／基本情報の4段階で正答率を比べます。
  差が20ポイント以上あると「用語は覚えたが使えていない」といった偏りが見えます。
- **単元別の理解度マップ** — 全単元を 定着（80%以上）／あと一歩（60%以上）／要復習（60%未満）／未受験 で色分けします。
  色だけに頼らず、必ず文字ラベルと数値を併記しています。押すとその単元へ移動します。
  デジタル分野の1列に並べています。
- **いま優先して立て直したい単元** — 正答率の低い順に最大3単元。単元ごとに「つまずいている可能性」
  「間違えた問題で問われていたこと」「こうすれば分かるようになります（実験番号つきの手順3つ）」を表示します。
- **間違えた問題の復習リスト** — 自分の答え・正解・解説を並べた一覧を、折りたたみで表示します。
- **単元別の記録** — ダッシュボードの下に、全11単元の実験の実施数と確認問題の得点を並べています。

学び直しの手順は、単元データの `remedy` に単元ごとに書いてあります（`lessons-digital.ts`）。
文言を変えたい場合はそこを直してください。

状態の色は、色覚多様性を考慮した検証（CVD分離 ΔE 11.2 / 通常視 22.1）を通しています。

## 分野別テスト

普段の学習とは別に、**デジタル分野100問・100点**のテストがあります。
先生が当日に伝えるパスワードで開きます。

### 仕組み

- **問題そのものを暗号化**して置いてあります（AES-GCM 256bit／PBKDF2 31万回）。
  パスワードを聞くまで、ソースを見ても問題は読めません
- パスワードは**クラスごとに別**です。他のクラスのパスワードでは開きません
- 4桁番号（学年1けた＋組1けた＋出席番号2けた）から**クラスを自動判定**します
- **出題順と選択肢の並びは生徒ごとに違います**。隣の画面を見ても写せません
- 問題そのものはクラス内で同じなので、**問題ごとの正答率を出して授業に生かせます**
- 追試は**その生徒専用のファイル**を作ります。他の生徒の番号では開きません

### 100問の内訳

| | 問題数 | クラスごとの違い |
|---|---|---|
| 自動生成 | 85問前後 | テンプレート186本から。**数値も答えも全部違う。文面の重複ゼロ** |
| IPA枠 | 15問前後 | 問題プール137問（IPA過去問40＋過去問風オリジナル97）から。**重複は最大8問** |

- **観点は必ず 知識・技能60問／思考・判断・表現40問**
- 単元も均等（デジタル11単元に7〜11問）
- 1問1点。提出するとその場で採点され、正解と解説が出ます
- 答えは自動保存されるので、途中でページを閉じても続きから再開できます
- 提出後の結果画面から**パスワード画面へ戻れます**。ページを開き直さなくても、
  追試などの別のパスワードを入れて受験できます（前の結果は保存されたままです）

### 問題を作るには

このリポジトリには**暗号ファイルしか入っていません**。問題の平文と生成の仕組みは、
別配布の「分野別テスト生成キット」に入っています。先生の手元だけで動かしてください。

```bash
npx tsx build-exams.ts --salt "合言葉" --out ../info_23_ddl/public/exams
```

合言葉を変えると、問題もパスワードも全部変わります。同じ合言葉なら何度でも同じものが再現されます。

**`public/exams/` に入っているファイルは動作確認用です。本番前に必ず自分の合言葉で作り直してください。**

### 気をつけること

採点は生徒のブラウザの中で行われます。パスワードを入れたあとは、開発者ツールを使えば
正解を見ることも点数を書きかえることも可能です。**先生が見ている場での実施**を前提にしてください。

## 公開版の方針

- 生徒氏名や名簿データは含めません。
- 入力する識別子は半角数字4桁だけです。全角で打っても半角に直します。
- 学習結果は利用中のブラウザの `localStorage` に保存します（キー: `joho-ddl-public-v2:` + 4桁番号）。
- 成績画面から `4桁番号_ddl_YYYYMMDD.json` を出力できます。
- JSONファイルを回収し、ExcelやPower Queryで集計する運用を想定しています。

### 4桁番号の確認と確定

打ち間違いと取り違えを防ぐため、番号は**確認してから確定**する方式です。

1. 4桁そろうと「**1205 ですね？**」の確認カードが出ます
2. あわせて、**このブラウザにその番号の記録があるかどうか**を表示します
   （「確認問題 3単元送信済み・実験 12個。続きから始めます」／「記録はありません。新しく始めます」）
3. ［はい、1205 で始める］で確定。［入力し直す］でやり直せます
4. **確定すると入力欄は消え**、「番号 1205（確定）」の表示に変わります。番号を変えるボタンはありません
5. 確定した番号は端末に記憶され、**次に開いたときも同じ番号で続きから**始まります

共用パソコンで次の人に渡すときだけ、［学習を終了］で番号の入力に戻せます。
押し間違いを防ぐため2段階（［学習を終了］→［終了する（記録は残ります）］）にしてあります。
記録そのものは消えないので、同じ番号を入れ直せば続きから再開できます。

なお、この確定はあくまで**取り違え防止**です。ブラウザのサイトデータを消せば解除されます。
他人の記録を本当に守る必要がある場合は、番号に加えて生徒だけが知る暗証番号が必要です。

### 別のブラウザでは続きから始められません

学習結果はブラウザごとに別々に保存されます（`localStorage` の仕様）。
ChromeとEdgeは同じパソコンでも別の保存場所になるため、**ブラウザを変えると記録は引き継がれません**。
次の場合も記録が消えることがあります。

- 情報教室の復元ソフト（再起動で初期化）
- シークレット／プライベートウィンドウ
- Safari（iPad・iPhone・Mac）で1週間以上開かなかったとき
- 履歴・サイトデータの削除

大事な記録は、成績ページからJSONを保存しておいてください。

**集計のしかた**

- `results` は日本語のまま出力しています。Power Queryでそのままピボットできます。
- `answers` が1回目、`retries` が2回目の選択肢番号（0始まり）。2回目に挑戦していない問題は `-1` です。
- `score` は 1回目正解×1点 ＋ 2回目正解×0.5点。単元の満点は問題数と同じです。
- `summary.totalScore` と `summary.areas[0].totalScore` は、どちらもデジタル分野の100点満点です。
- クラス全員のJSONを1つのフォルダに集めれば、`summary` から一覧表がすぐ作れます。
- `wordSubmissions` は重要語句テストの記録です。`answers` が1回目、`retries` が2回目に**実際に打った文字列**なので、
  どんな書き方で間違えたのかがそのまま残ります。次の年の許容表記を足すときの材料になります。
- `missionNotes` は応用ミッションの自由記述です。空欄のまま記録した場合、その実験は0.5個ぶん・0Gとして扱われます。
- `coins` はGの収支です。**成績には使いません。**
- `understanding` は実験ごとの理解度の申告（1〜5）。キーは `experiments` と同じ `単元ID-実験番号` です。
  未申告の実験はキー自体がありません（0点として集計されます）。
- `summary.understandingScore / understandingMax` が理解度の合計と満点、
  `perspective.attitude` がその割合（％）です。主体性の資料としてお使いください。

`exams` に分野別テストの結果が入ります（成績処理はまずここを見れば足ります）。


v5以前のJSONとは互換性がありません。ただし**ブラウザに保存済みの旧データは自動で読み直します**
（2回目の記録がない問題は「2回目待ち」として扱われ、続きから解答できます）。

## ファイル構成

```
app/
  page.tsx                 画面全体（学習マップ・単元・成績・JSON出力）
  layout.tsx               ルートレイアウト
  globals.css              全スタイル
  lib/
    types.ts               型定義
    calc.ts                計算ライブラリ（基数変換・補数・浮動小数点・統計・検定）
    ui.tsx                 実験の共通部品（入力欄・結果表示・グラフ）
    lessons.ts             単元データの統合
    lessons-digital.ts     デジタル分野11単元
    progress.ts            G・レベル・こころの計算
    words.ts               重要語句55語（正解・問題文・許容表記）
    word-check.ts          入力の照合（表記ゆれの吸収）
    word-quiz.tsx          重要語句テストの画面
    hint-list.ts           有料ヒント37個の一覧（実験26＋重要語句11／中身は持たない）
    roster.ts              使える4桁番号の名簿
    question-figures.tsx   確認問題に添える図（D5 Q2 など）
    mojibake-data.ts       文字化けの実物データ（D6 実験3）
    sheet.ts               応用の簡易表計算（式の評価／現在は未使用）
    mini-sheet.tsx         応用の簡易表計算（画面／現在は未使用）
    sheet-tasks.ts         応用の簡易表計算の問題（データ活用分野用のため、この版では出番なし）
  experiments/
    index.tsx              単元IDから実験を呼び分ける
    digital.tsx            デジタル分野の実験
```

計算はすべて `lib/calc.ts` に集約しています。統計関数（正規分布・t分布・カイ二乗分布）は
SciPyと小数点以下8桁まで一致することを確認済みです。
