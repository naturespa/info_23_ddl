# DDLのJSONを校内サーバーへ送る

既存の「JSONを保存」はそのまま使えます。「ステータス」のJSON保存欄の下にある「JSON送信」は、同じ内容を指定したNode.jsサーバーへ送ります。GitHub Pages自身には成績を保存しません。

## 1. 先生側：受信サーバーを準備する（Windows）

1. Node.js 22以降をインストールした校内の受信用PCを用意します。
2. このリポジトリの `local-server` 内の `server.cjs` と `start.bat` を `C:\ddl-json` にコピーします。既存の `C:\cbt` とは別のフォルダーです。
3. コマンドプロンプトを開いて実行します。追加のnpmインストールは不要です。

```bat
cd /d C:\ddl-json
node --version
node server.cjs
```

`start.bat` のダブルクリックでも起動できます。終了するまでウィンドウを開いておきます。終了は Ctrl+C。再起動後はもう一度起動してください。

4. 同じPCのブラウザで `http://localhost:3002/health` を開き、`"ok":true` を確認します。
5. コマンドプロンプトで `ipconfig` を実行し、校内LANのIPv4アドレスを確認します。例えば `192.168.1.50` なら、生徒へ伝える送信先は `http://192.168.1.50:3002` です。生徒PCでlocalhostと入力すると、生徒PC自身を指してしまいます。
6. 学校の管理方針に従って、受信用PCのTCP 3002番へ校内の生徒端末から接続できるよう設定します。固定IPまたはDHCP予約を利用すると送信先が変わりません。

pycbtの3000番、HTML収集の3001番と分けるため、既定は3002番です。本サーバーに管理画面はありません。

## 2. 生徒側：送信する

1. https://naturespa.github.io/info_23_ddl/ を開き、4桁番号で学習します。
2. 「ステータス」の「JSON送信」に先生から指定された送信先を入力します。
3. 「JSON送信」を押し、確認画面で番号と送信先を確認します。
4. ブラウザがローカルネットワークへのアクセスを求めた場合は、学校の指示に従って許可します。
5. 受付番号と「保存しました」が表示されれば完了です。成功した送信先だけ、そのブラウザに記憶されます。自動送信はしません。

## 3. どこに保存されるか

上の手順では **受信用PCの `C:\ddl-json\data`** に保存されます。生徒PCやGitHubには送信データを保存しません（従来のブラウザ内の学習記録は継続）。

例：`0101_2026-09-29T10-20-30-000Z_受付番号.json`

内容はJSON保存と同じversion 6のStudentRecordです。送信時刻 `exportedAt` を含みます。ファイル名の時刻はサーバーで受信したUTC時刻です。受付番号からファイルを探せます。同じ番号の再送は別ファイルになるため、集計時には再提出を確認してください。データには学習記録・得点・自由記述を含みます。

サーバーは形式を確認して保存しますが、得点の再採点・受験者本人の認証・名簿照合はしません。CORSの許可は認証の代わりにはなりません。校内LANで使用し、インターネットへポート公開しないでください。保存フォルダーは担当者だけが読み書きできる権限にし、学校の運用に従ってバックアップしてください。HTTP通信は暗号化されないため、必要な環境では学校管理のHTTPS入口を用意してください。

## 4. 送信できないとき

- 起動ウィンドウが閉じていないか、IPと3002番が正しいか確認します。
- 生徒PCから `http://受信PCのIP:3002/health` が開けるか確認します。開けない場合はLANの分離、ファイアウォール、学校のプロキシ設定等を管理担当者と確認します。
- healthが開けても、HTTPSのGitHub PagesからHTTPの校内サーバーへの送信は、ブラウザの混在コンテンツ制限・ローカルネットワーク許可・学校の管理設定で拒否される場合があります。CORSだけでは解除できません。学校が管理する有効な証明書のHTTPS入口を設けるか、許可された校内配信構成を管理担当者と検討してください。ブラウザのセキュリティ機能を一括無効にしないでください。
- 15秒で応答が確認できない場合は失敗扱いです。サーバーに保存済みで応答だけ届かなかった可能性があるため、先生がdataを確認してから再送します。
- すぐ提出する必要があれば「JSONを保存」でファイルを残してください。
- 最大2 MiB。超える場合はJSON保存で提出します。

まずサイトで使用できる確認用の番号で1件送り、受付番号に対応するファイルの番号・内容を確認してからクラスで利用してください。

## 5. 任意の設定

コマンドプロンプトで、起動前に環境変数を指定できます。

```bat
set PORT=3002
set DATA_DIR=C:\ddl-json\data
set ALLOWED_ORIGINS=https://naturespa.github.io
node server.cjs
```

`ALLOWED_ORIGINS` はページのオリジン（パスなし）。複数はカンマ区切り。開発中だけlocalhost:3000も許可する例：`https://naturespa.github.io,http://localhost:3000`。`HOST=127.0.0.1` を設定すると同じPCからだけ受信します。既定ではLANからの接続を受け付けます。

## 引き継ぎ用の仕様・検証

- UI: `app/lib/json-submit.tsx`。学習記録画面から既存の `buildRecord()` を受け取る。
- `POST /api/submissions`、Content-Type application/json。本文はStudentRecordそのもの（ラッパーなし）。
- 保存完了後にHTTP 201と `{ok:true, studentCode, receiptId, receivedAt}` を返す。
- 400=不正JSON/形式、403=許可外Origin、413=容量超過、415=Content-Type不正、500=保存エラー。
- `GET /health` は稼働確認のみ。記録の一覧取得・公開・削除APIは設けない。
- 自動テスト: リポジトリ直下で `node --test local-server/server.test.cjs`。
- サイトのビルド: `npm ci` の後、Windowsでは `set GITHUB_PAGES=true`、次に `npm run build`。
- 学校の実ネットワーク・管理ブラウザからの送信確認は導入時に別途実施する。
